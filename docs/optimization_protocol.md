# 四分类 mAP50 优化协议

## 基准约定

- 主要指标和验收目标：在 IoU 0.50 下，四分类 COCO 边界框指标达到 `mAP50 > 0.95`。
- 辅助定位诊断指标：`mAP50-95`、`mAP75`，以及小/中/大目标 AP。这些指标不用于判定是否达到主要目标。
- 数据集：`credible_fine_v2`，指纹为 `e45e9272436fcaea448f4e4edc7c252989f5be3db8b1a8400a5ba97d034e97e1`。
- 开发阶段使用 `val`。锁定的 `test` 划分仅用于评估最终候选方案。
- 报告总体 AP、AP50、AP75、小/中/大目标 AP、各类别 AP、正常图像误报率，以及 bootstrap 95% 置信区间。
- 来自其他数据指纹的结果属于不同基准，不得写入同一个排行榜直接比较。

## 数据证据

新增的 Supervisely 数据包含来自 322 个图像组的 1296 个有标注文件。其独立的 160 文件 Test 压缩包没有标注，因此不参与训练和评估。文件名以 `d`、`h` 和 `v` 结尾的是派生变体；同一图像组的所有变体必须保留在同一数据划分中。数据采用 CC BY 4.0 许可：

- https://github.com/supervisely-ecosystem/aerial-power-infrastructure-detection-train-dataset
- https://github.com/InsulatorData/InsulatorDataSet

`build_credible_dataset.py` 还会对完全重复图像和采用保守差异哈希判定的近重复图像进行分组。划分清单、重复图像报告、数据来源分布、标签数量和数据指纹均保存在 `metadata/` 下。

400 张图像的审计优先覆盖全部 CPLID 合成缺陷图像和最小的边界框。人工审核结果为 `approved` 的行予以接受。`pending` 表示审核者无法判断边界框是否正确；这些行不得视为已通过标签，也不得作为伪标签加入数据集。

已完成的候选标签审核在 41 张仅训练集图像中接受了 44 个边界框，包括 16 个 `broken_shell`、25 个 `flashover_pollution` 和 3 个 `missing_disc_drop`。验证集和测试集的标签及图像成员关系与 v1 逐字节相同，因此没有降低基准难度。使用这些新增标签进行低学习率 YOLO11s 微调后，AP50 仅达到 `0.7716`，因此该方案被淘汰。

已发表的 Insulator-DET 数据集可以增加 2150 张图像，并可将 `broken-disc`、`flashover` 和污秽类别映射到本任务，但作者提供的 Kaggle 下载端点目前返回 HTTP 404。本项目没有导入未经许可的镜像。现有采用 CC BY 4.0 许可的合成破损绝缘子数据集仅包含约 200 张图像，而且由 7 张正常源图像生成，数据多样性不足，不适合混入可信的真实图像基准。如果能够获得访问权限，官方 IDID/EPRI 数据仍是补充真实标签的首选来源。

## 实验门控条件

1. 在 `data_unbalanced.yaml` 上以 960 输入训练 YOLO11s，作为参考基线。
2. 使用相同的 YOLO11s 权重、数据划分、随机种子、图像尺寸、batch 大小、余弦学习率计划和 Mosaic 关闭时点，进行受控的 40 epoch 数据增强筛选。分别训练 `none`、`defect_safe` 和 `moderate`；根据验证集 mAP50 和“缺陷类别不得下降”门控选择方案，并且只将获胜方案延长到完整训练周期。`defect_safe` 预设会限制 HSV、缩放、几何变换和 Mosaic 强度，因为激进变换可能抹除较小的掉片目标，或者改变污秽特征。
3. 使用获胜的数据增强预设和稀有类别重采样，在 1280 输入下训练 YOLO11m-P2。只有当验证集 mAP50 至少提高 `0.02`，且任一缺陷类别 AP50 的下降不超过 `0.03` 时，才保留该模型。
4. 在混合切片数据集上训练，并比较标准推理、SAHI 推理和混合推理。切片方案采用相同的保留门控。
5. 如果 AP50 较强但主要差距来自 AP75，则评估 D-FINE。如果主要问题是类别混淆，则将剩余预算用于修正标签和重新训练。
6. 使用另一个随机种子重新训练获胜配置，并且最多只在锁定测试集上评估两个最终候选方案。

GPU 预算上限为 30 小时。如果连续三个已完成实验的验证集 mAP50 提升均小于 `0.01`，则缩短或终止后续运行。最终目标是在锁定测试集上达到严格的四分类 `mAP50 > 0.95`。仅有验证集成绩不能视为最终达标，也不得通过改变数据划分或置信度阈值制造达标结果。

## 已测数据增强消融实验

受控的 YOLO11s@960 验证实验最终选择了 `moderate` 数据增强。所有报告均使用针对 AP50 保存的专用最优检查点：

| 预设 | mAP50 | insulator | broken | pollution | missing |
| --- | ---: | ---: | ---: | ---: | ---: |
| moderate | 0.7754 | 0.9493 | 0.6058 | 0.6245 | 0.9221 |
| defect_safe | 0.7501 | 0.9503 | 0.5649 | 0.5835 | 0.9017 |
| none | 0.6144 | 0.9280 | 0.3366 | 0.3645 | 0.8284 |

无数据增强的实验发生过拟合并提前停止。与无增强相比，`moderate` 将总体 AP50 提高了 `0.1610`，因此后续 P2 和切片实验均采用该预设。两个弱类仍是 `broken_shell` 和 `flashover_pollution`，说明仅依靠数据增强不足以达到 0.95。

最初的 YOLO11m-P2 1280/batch-4 可行性实验占用约 11.46 GB 显存，在 RTX 4080 Laptop GPU 上运行 34 分钟仍未完成首个 epoch。预计运行时间超过剩余实验预算，因此最终保留 P2@960、batch 6 配置。该配置保留 P2 检测头和平衡训练视图，同时将像素计算量降低 43.75%。

采用权威的方形 letterbox 协议重新评估后，P2@960 的验证集 mAP50 为 `0.7799`，YOLO11s 为 `0.7754`。早期报告使用 Ultralytics 的矩形 batch 推理，图像几何会随 batch 组成发生变化；`evaluate_detector.py` 现在强制所有标准评估路径使用 `rect=False`。基线模型的标准 SAHI 推理仅达到 `0.6867`，低于基线，因此不保留切片方案。其主要失败原因是在密集 IDID 缺陷标注附近产生额外的定位误报，而不是发生跨类别混淆。

YOLO11s 切片微调在第 10 个 epoch 后停止，mAP50 为 `0.7322`；其最佳轨迹仍比全图基线低 `0.0433`，未通过继续训练门控。对应检查点和曲线作为负面实验结果保留。

## 密集标注与 ROI 迭代

验证集混淆矩阵中没有明显的跨类别错误。大部分错误是缺陷预测被匹配为背景，或者缺陷真实框被漏检为背景，并且主要集中在具有大量逐片标注的 IDID 派生图像中。已发表的 IDID 分析指出密集排列场景中存在标注不完整问题，因此未匹配的高置信度预测更适合作为正例-未标注审计候选，而不能直接视为负例。

因此，`credible_fine_v1_crops` 会以 15% 上下文范围裁剪每个有标注的绝缘子串。仅训练集使用的中心点/尺度抖动可生成 9174 个物理裁剪；高效训练视图保留全部 3058 个基础裁剪，并且仅为正样本裁剪添加一次抖动，共得到 4974 个唯一训练条目。验证集和测试集对每个绝缘子串只使用一个确定性裁剪。在 960 输入下，缺陷框中位尺寸约为 147×83 像素，验证集和测试集中面积小于 $32^2$ 像素的边界框不足 2%。局部检测器是三分类 YOLO11s，全局模型则保留四分类全图预测和绝缘子框。端到端方案是否保留，只根据原始全图验证集判断。

局部模型在裁剪验证集上的 mAP50 为 `0.7040`，三个缺陷类别分别为 `0.5607 / 0.6490 / 0.9023`。全图两阶段结果分别为：并集 `0.7747`、局部优先 `0.7687`、仅局部 `0.7688`，均低于 `0.7754` 基线。基线 TTA 为 `0.7575`；基线与 P2 加权融合为 `0.7748`。这些推理路径均未被保留。

当至少两个模型对一个未匹配缺陷达成一致时，`mine_missing_labels.py` 会创建仅针对训练集的审核包。该脚本不会修改标签，也不得在锁定验证集或测试集上执行模型驱动的标签修正。

下一种架构候选方案是在 P3/P4/P5 特征后添加受 TLINet 启发、依赖较少的 Context-Guided 增强模块。该方案保持 YOLO11s 主干和颈部索引不变，并明确迁移当前四分类检查点中形状兼容的 Detect 张量，从而将上下文模块的影响与从头重新训练检测头的影响区分开。

## 已完成的模型搜索与当前上限

下表所有数值均采用固定的 `rect=False` 方形 letterbox 验证协议和原始四分类标签：

| 候选方案 | mAP50 | 结论 |
| --- | ---: | --- |
| YOLO11s moderate 基线 | 0.7754 | 参考基线 |
| YOLO11m-P2 | 0.7799 | 互补模型 |
| 基线 + P2 WBF | 0.7922 | 保留 |
| 基线 + P2 + ROI | 0.7949 | 保留 |
| 仅上下文模块微调 | 0.7723 | 淘汰 |
| 仅训练集高精度伪标签 | 0.7673 | 淘汰 |
| 标准 YOLO11m 检测头微调 | 0.7581 | 淘汰 |
| 平衡数据、冻结主干的 YOLO11s 微调 | 0.7700 | 淘汰 |
| 基线 + P2 + 缺陷专家 + ROI | 0.7986 | 保留 |
| D-FINE-M，COCO 预训练 | 0.8257 | 保留 |
| D-FINE-M，Objects365→COCO 预训练 | 0.8080 | 淘汰 |
| D-FINE-L，固定 960 输入 | 0.8177 | 仅作为定位候选 |
| YOLO 集成 + D-FINE-M + D-FINE-L | **0.8375** | 当前验证集最佳 |

当前最佳方案的逐类 AP50 为 `0.9651 / 0.7726 / 0.6651 / 0.9474`。经过 200 次重采样得到的 bootstrap 95% 置信区间为 `[0.8058, 0.8735]`。与原始 YOLO11s 基线相比，总体提高 `+0.0621`，但距离 `0.95` 目标仍差 `0.1125`。剩余差距几乎全部来自 `broken_shell` 和 `flashover_pollution`；增加模型容量、上下文模块、切片、ROI 裁剪、通用伪标签、长尾检测头微调、更丰富的通用预训练和检测器集成都没有消除这一差距。

D-FINE-M 是最强的单检测器，AP50 为 `0.8257`。D-FINE-L 提高了 AP75 和 AP50-95，但没有提高 AP50，说明额外的定位容量已经不再是主要限制因素。Objects365→COCO 预训练也弱于仅使用 COCO 预训练的 M 检查点。最终 M+L 融合相对于以 M 为基础的完整集成仅增加 `0.0027` AP50，已经满足因架构收益递减而停止实验的条件。

`make_class_projection_dataset.py` 可以在不修改可信源数据的情况下，创建采用硬链接并带有指纹的专家数据集。三缺陷专家模型的内部 mAP50 为 `0.7135`，在集成中提供了少量互补增益。仅使用 IDID 的破损/污秽专家模型仅达到约 `0.61`，该结果更支持“不完整标注”诊断，而不是“数据源域模型容量不足”诊断。

当前已经满足模型搜索停止条件：多个连续且有效的架构/数据训练实验提升均小于 `0.01`。由于验证集结果远低于验收目标，锁定测试集仍未使用。候选框审核已经完成，但这并不是穷尽式标注审核。若要可信地继续冲击 `0.95`，需要补充具有完整标注的真实 `broken_shell` 和 `flashover_pollution` 图像，并由独立专家检查验证集中每一个弱类别实例。不得使用模型生成的边界框修改验证集或测试集标签。
